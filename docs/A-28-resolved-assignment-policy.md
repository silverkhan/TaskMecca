# Retiring obsolete assignment observation warnings

The operations monitor reads the unique current canonical task, authoritative lifecycle transitions, durable assignments and runtime observations on every scan. It does not edit these sources, create a runtime terminal event, complete a task, resume a hold, or change notification delivery.

A canonical done task needs substantive result and verification plus the latest Controller-owned completed transition with substantive evidence. Both `controller_verified` and legacy `controller_report` are supported. Legacy reports without assignment/attempt IDs establish a task-wide boundary covering earlier assignments, including parallel child assignments. Explicit IDs must match durable identities. New assignments, lifecycle reopening, malformed/ambiguous/unavailable evidence, future timestamps, and applicable late runtime activity fail closed.

An active user/external/dependency hold needs explicit released ownership (`Agent: -` and `변경범위: -`), meaningful waiting reason, resume condition and evidence, plus a latest Controller-owned waiting transition. A Controller-owned `worker_report` can record a verified waiting report; a Worker actor alone cannot. The resolution is **released hold**, never task completion.

Only ordinary observation warnings (`runtime_unknown` identity gaps, `no_signal`, `handoff_stalled`) can be retired by this policy. Actual errored/interrupted/shutdown states, unconfirmed terminal-error claims and `handoff_failed` stay actionable. No source clocks are based on polling or file modification time. Current stage output omits retired assignments rather than displaying them as pending work. Recovered incidents retain their original evidence and a separate `policy_resolution` containing the current task path, lifecycle event, source, reason and boundary.

Runtime scope matters: pre-assignment/manual-bound legacy attempts without an assignment ID remain separate evidence. They cannot retire attempt warnings, but unrelated legacy attempts do not reconstruct an assignment-only pending stage. A same-identity assignment/attempt already started before the boundary may finish reporting after a release/completion when a real observed/authoritative Hook proves completed terminal state. There is no arbitrary grace extension: activity after that terminal, a fresh binding/start/assignment, a new applicable attempt or actual failure remains actionable. Still-running late activity is not reporting closure.

Successful Controller handoff claim/acceptance/cleanup/applied bookkeeping after canonical completion is not new Worker execution. A real failed matching handoff stage still produces its independent immediate failure warning. An old failed source does not justify repeatedly reconstructing an unrelated historical assignment stage.

Historical exact-source recovery by a newer observed assignment is no longer unconditional: the unique current active doing task and latest durable ownership must still agree with observed runtime evidence. Missing or ambiguous current policy cannot blindly reuse an old permanent suppression signature. Repeated scans and restarts preserve incident IDs and do not start another stale notification episode; notification transport/ledger behavior is unchanged.

It calls only read-only catalog/lifecycle/assignment/runtime/handoff projections, never monitoring scans/reconciliation/registration against operational projects, and emits sanitized metadata instead of payloads. Normal tests use isolated synthetic projects. Production deployment and actual Web/API before/after verification belong to the Controller.
