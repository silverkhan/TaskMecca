# Reviewer continuity interface (A-91)

Status: implementation contract for `internal/reviewcontinuity`; A92's DTO adapter and rendering are not connected by this document. A90 owns `rolepolicy.ReviewRequest`, roles and risk decisions.

`Assess(workspace, Input)` is read-only. `Input.Current` is a `Snapshot` containing the exact `ReviewRequest`, `chain_id`, nullable `review_round`, `session_generation`, observed `state`, and immutable report/findings/errors/validation/remaining-step evidence. `ReviewRequest.continuity_ref` and `context_ref` remain optional evidence references, never authorization. `Input.Continuity` and `ContextRef` supply the corresponding path plus SHA256. References must be relative, confined to the evidence workspace, hash-matched files. Unknown identity/source/link evidence fails closed.

`Result.purpose="review"` and `purpose_verified=true` require current task/assignment/contract, complete source hashes read from disk, a bound observed Reviewer identity, independent verified implementation history, and a non-omitted necessity decision. A name, role title, running session or saved report alone cannot establish purpose or acceptance. `necessity` uses A90's decision; `actual_state` is separately supported by a current attempt-bound `Observation`. Missing observation means `unknown`; request/START/result evidence remain distinct. This module does not grant execution or independent acceptance.

`chain_id` identifies explicitly linked work; `review_round` is nullable and never derived from generation or session creation. `session_generation` describes the managed session, `request.reviewer.attempt_id` the actual execution. Reusing an animal name proves none of these. Prior snapshots retain their own task, assignment, contract, source, native/attempt, report reference, findings and original errors. `source_delta` lists changed/added/removed paths; prior accepted outcomes are never promoted to current acceptance.

`BuildCheckpoint` captures immutable snapshots plus the existing CLM checkpoint and a fingerprint. `ReadCheckpoint` verifies bytes, fingerprint and report references before reuse. A successor must supply the checkpoint reference and independently revalidate its current source and identity. Checkpoint saved, native session created, link verified, review started and result recorded are separate events. Neither checkpoint creation nor this module starts a session, changes a ledger, compresses context or acknowledges a rotation.

`Input.Host` carries exact host kind, supported/unsupported/unknown reuse capability and explicit policy. T3 always yields `new_delegate_task`, including rechecks: carry the checkpoint into a **new** `delegate_task`; `t3_thread_send` is not a new review. Other hosts permit `reuse_session` only for the exact verified previous identity/attempt, current running observation, no conflicting assignment, unchanged current source, policy permission and measured CLM context below 65%. Unknown/unsupported capability, context, identity or source cannot authorize reuse. A new session inherits evidence, never acceptance.

`Input.Context` is the existing `contextlife.StatusReport`, tied to the current reviewer role/attempt and `context_ref` bytes. `context_status` stays unknown without matching evidence. Existing trust and 65/80/90 prepare/rotate/protect decisions remain authoritative. Reviewer idle events are `review_completed` and `review_iteration_completed`; they request preparation, without claiming automatic rotation success. Existing prepare/acknowledge/commit gates validate the successor and retain failed rotations. No token estimator or polling is added.

Fixtures demonstrate local decisions only. Actual T3 handoff, independent review, Controller acceptance and dev/CI/release evidence are separate downstream gates.

## HTTP projection

Every workflow response, including cache hits, adds `control_snapshot.reviewer_presentation`. Workload list/detail and task detail add the same payload under top-level `reviewer_presentation`. Existing JSON keys, timeline axis, measurements and denominators are preserved. The adapter reads persisted evidence only and does not launch provider tools. `version=1`, `by_attempt` is keyed by exact attempt ID, and `task` contains `necessity`, `actual_state`, `reason`. Each attempt entry has these exact JSON tags:

```json
{"attempt_id":"run-fixture","native_id":"native-fixture","task_id":"A-fixture","official_name":"","name_verified":false,"name_source":"","name_observed_at":"","purpose":"unknown","purpose_verified":false,"necessity":"unknown","actual_state":"unknown","chain_id":"","review_round":null,"session_generation":null,"context_status":"unknown","continuity_ref":"","context_ref":"","source_delta":[],"errors":[]}
```

Consumers must join `attempt_id` **and** `native_id`; neither a display alias nor a previously visited task selects an entry. Names require persisted `RootNameObservation` verified identity/provenance and the matching native T3 receipt; missing or unavailable evidence clears the name. An official name can retain its literal G text; it never supplies `review_round` or the nullable `session_generation` field. Stored Worker roles are not rewritten to Reviewer when their verified purpose is review.

Purpose can be established from the current canonical typed review owner, complete scoped source snapshot, exact observed bound runtime identities and verified independent implementation history. This establishes assigned purpose, not review progress or acceptance. Progress needs matching review Activity. Necessity comes only from the current typed A90 requirement. Optional `_task_mecca/.runtime/reviewer_continuity/<attempt>.json` contains `{policy_sha256,input}`; only an exact current policy digest, contract fingerprint, complete current source and identities allow `Assess` to add continuity fields. The loader replaces supplied implementation history with actual persisted runtime identities. This is a read contract, not a new writer or automatic migration; absent evidence stays unknown.
