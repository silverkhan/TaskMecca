# Task Mecca 실행 환경 전환 (Stable · Dev · PR)

## 개념

기존 Stable/Dev는 릴리스 채널이다. PR은 Dev에서 명시적으로 선택하는 **특정 Commit SHA의 전체 실행 환경**이다. PR 환경은 실제 프로젝트/백로그/Root Session/Hook/알림을 사용한다. 복제된 샘플 Preview, 추가 포트 또는 중복 감시 서비스가 아니다.

## Dev → PR

1. Dev Web의 **PR 실행 환경**에서 GitHub Actions가 성공한 같은 저장소의 PR 및 현재 SHA를 선택한다.
2. 코드를 신뢰하는 경우에만 명시적으로 실행을 승인한다. PR 코드는 기존 사용자와 동일 OS 권한을 가진다. 빌드 SHA256/PR 매니페스트 검증은 **무결성** 검증이지 악성 코드 방어가 아니다.
3. 정확한 PR 번호/HEAD SHA, workflow run, OS/아키텍처 체크섬을 검증한다. **빌드된 바이너리의 `environment capability` 응답**을 CI가 확인한 아티팩트만 전환할 수 있다. 이전 Preview만 지원하는 PR은 실행 전환을 거부한다.
4. 실행 중인 Dev 실행파일을 `TASK_MECCA_HOME/environment-switch/dev-<SHA256>.bin`에 해시 검증해 보존한다. 전환 원장은 `execution-transition.json`, 현재 실행 타깃은 `execution-target.json`에 기록한다.
5. 기존 설치 경로/웹 포트를 유지하며 실행 파일을 교체하고 웹 서비스를 재시작한다. `/api/health`의 boot ID와 실제 실행 타깃 PR/SHA가 달라졌을 때 전환을 확정한다.

## PR → Dev

- 활성 PR의 상단 배너에서 **Dev 복귀**를 선택한다. 복귀 대상은 **PR 진입 직전 Dev 바이너리**이며, 최신 Dev를 자동으로 내려받지 않는다.
- 실행 파일과 서비스가 재시작되면 실제 실행 바이너리의 SHA를 대조하여 PR 실행 기록을 정리한다.
- 이 과정은 **프로젝트 데이터/프레임워크/라이프사이클 원장을 되돌리지 않는다**. PR이 저장 구조를 변경하면 이전 버전과 호환되지 않을 수 있다.

## 중단 및 복구

- 설치 및 재시작 직전에 기록한 전환 원장은 프로세스 강제 종료 후에도 남는다. 다음 부팅 시 실행 바이너리가 목표 해시이면 전환을 확정하고, 이전 바이너리 해시이면 실패 롤백으로 정리한다.
- 양쪽 해시 어느 것과도 일치하지 않거나 상태 파일이 손상된 경우에는 임의로 마이그레이션하거나 Dev로 판정하지 않고 실패한다.
- 기존 재시작 watchdog이 재시작 실패를 처리하도록 한다. 추가 조치가 필요한 경우 `task-mecca web logs`, `task-mecca web status`를 확인하고, `execution-target.json`의 보존된 Dev 파일과 SHA256을 대조한 뒤 복원한다. 원장 파일을 임의로 삭제하지 말 것.
- 수동으로 바이너리를 복원해야 할 때는 원장에 보존된 Dev 경로와 SHA를 정확히 확인하고 설치 경로의 실행 파일을 복구해야 한다. macOS/Linux에서 실행 파일 교체와 웹 재시작의 운영체제별 권한/서비스 정책에 주의한다.

## 제한 및 향후 작업

- **Windows PR 전환은 현재 비활성화:** 기존 Windows 릴리스 업그레이드는 `.new` 예약 교체를 사용한다. PR 전환은 교체/웹 재시작/health 확인 순서가 검증될 때까지 열지 않는다. 기존 Stable/Dev 전환은 유지한다.
- 미신뢰 Fork PR을 자동 실행하지 않는다. 다른 기여자는 자신의 머신에서 신뢰 가능한 PR을 검증하되, Fork 지원은 별도의 신뢰·빌드 검증 정책으로 확장한다.
- 운영 Hook/라이프사이클/Telegram 실사용 전후 이력 비교, 대규모 백로그 UI 확인, 비정상 종료 복구 및 Mac/Windows/Linux E2E는 AID-154 검증 항목이다.
- 기존 독립 Preview 실행은 비활성화한다. 과거에 띄운 Preview를 종료하는 API는 정리 용도로만 유지한다.
